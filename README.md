# Project Kickoff

一个面向 Codex 的项目启动 Skill。它帮助你在开始实现之前，把模糊想法收敛为有依据、范围明确、可验收、可交接的启动方案。

它适合学习项目、作品项目和实际软件项目，也适合已有项目中的较大新方向。重点是减少目标、场景和首版范围理解错误，而不是为了填满模板增加问题或文档。

## 适用场景

- 从一个想法开始新的软件项目
- 为已有项目规划一个较大的新方向
- 目标用户、使用场景、首版范围或验收仍有高影响不确定性
- 需要把讨论整理成后续开发可以使用的文档
- 需要在 UI 原型、实验或最小工程之间做有依据的阶段安排

不适用于普通 Bug 修复、单项文件修改、执行已经确认的实现计划，或只问一个独立技术概念的问题。

## 核心原则

1. 先调查项目起点，再提出问题；区分事实、文档声明、用户目标和未验证假设。
2. 一次只解决一个会改变当前方案的关键问题，不用固定问卷填满流程。
3. 把“智能”“方便”“快速”等抽象目标转成用户操作和可观察结果。
4. 对未知内容建立低成本验证任务，不把猜测写成已确认事实。
5. 需求确认、文档编写、代码搭建、测试、安装和发布属于不同授权范围。
6. 用户知情选择某个方案后记录该决定，不重复劝退；新证据改变前提时保留旧决定及替代关系。

## 工作方式

```text
调查项目起点
    ↓
确认目标、用户和具体场景
    ↓
收敛首版范围、主要流程、非目标和验收
    ↓
处理实验、UI 原型或其他关键不确定性
    ↓
保存启动记录、需求说明和阶段计划
    ↓
（单独授权后）搭建并验证最小可运行流程
    ↓
交接证据、未决项和下一阶段入口
```

每个决定会标明状态，例如：`已确认`、`建议`、`默认`、`待验证`、`已替代`。阻塞性验证还会记录输入、最小验证办法、判断依据、最晚决策阶段，以及通过、失败和无结果时的处理。

## 交付内容

项目规模不同，文档数量也可以不同。常见入口包括：

```text
docs/
├── kickoff.md                  # 决定、理由、讨论进度和授权边界
├── requirements.md             # 目标、场景、范围、非目标和验收
└── roadmap.md                  # 阶段目标、依赖、交付、验收和停止点
```

必要时再增加架构说明、项目规则或原型交接。已有项目优先沿用现有文档入口，避免产生互相矛盾的第二套资料。

启动交接会说明：

- 已确认决定及其来源
- 当前仍待验证的内容及受影响阶段
- 实际检查、运行或原型证据
- 当前授权范围和下一阶段所需授权
- 文件入口、停止点和复验方法

文档齐全不等于实施已获批准；条件性计划也不能把依赖未验证事实的阶段标为已就绪。

## UI 原型协作

当页面结构或关键交互会影响需求，但尚未确定时，Skill 可以交接给 [UI Prototype](https://github.com/td-xiehongyi/skill-ui-prototype)。

- 业务目标已清楚、只是布局或交互顺序待比较时，交接“探索方案”，允许候选原型验证判断。
- 已有确认设计时，直接引用版本和分项确认范围，不强制重新设计。
- 原型交付、浏览器检查和用户确认分别记录；视觉确认不等于业务规则或后端行为已确认。

UI Prototype 是可选协作 Skill，不是 Project Kickoff 的运行时依赖。

## 如何调用

在 Codex 中直接使用：

```text
使用 $project-kickoff，一次一个关键问题，帮我明确这个项目并制定分阶段启动方案，先完成文档，不写代码。
```

已有项目时，同时提供项目路径、现有需求入口或启动记录。若已有内容已经明确，Skill 会沿用它们，只处理真正新增或变化的问题。

如果已经明确授权搭建最小工程，应同时说明搭建范围和验收目标；仅授权文档时不会生成代码。

## 安装

将本仓库目录复制到 Codex 的个人 Skill 目录，目录名保持为 `project-kickoff`：

### Windows PowerShell

```powershell
$skillRoot = if ($env:CODEX_HOME) { Join-Path $env:CODEX_HOME 'skills' } else { Join-Path $HOME '.codex\skills' }
Copy-Item -Path . -Destination (Join-Path $skillRoot 'project-kickoff') -Recurse
```

### macOS / Linux

```bash
skill_root="${CODEX_HOME:-$HOME/.codex}/skills"
cp -R . "$skill_root/project-kickoff"
```

安装后重新开始一个 Codex 对话，或显式使用 `$project-kickoff`。

## 目录说明

- `SKILL.md`：运行入口、访谈边界和阶段交接规则
- `references/interview-strategy.md`：选择下一个关键问题的方法
- `references/documents-and-handoff.md`：文档、原型和工程交接约定
- `references/behavior-tests.md`：维护 Skill 时使用的行为场景
- `agents/openai.yaml`：Codex 界面展示信息
- `validation/`：格式、行为和交接验证记录，不是运行时指令

## 验证边界

维护时会分别记录结构校验、情景复核、真实文档往返、工程运行、UI 对照和安装后的触发验证。启动命令成功不等于 UI、安装或发布验收成功。当前验证详情见 [`validation/`](validation/)。
