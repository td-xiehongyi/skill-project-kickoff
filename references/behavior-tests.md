# 行为验收场景

仅在创建、修改或验证本 Skill 时读取。实际项目访谈不加载本文件，也不把这些场景变成用户必答问卷。

## 方法

先在未加载本 Skill 的独立上下文记录回答，再给另一个上下文相同原始材料并加载 Skill。保留实际回答，按决策与行为人工评估；不要用固定措辞、标题或关键词出现次数判定成功。

评估者仅接收案例原始材料和待测 Skill，不接收下表验收判据、先前答案或修复建议。案例之间独立；只读模拟不能证明真实文件写入或多轮工具交互成功。需要实测写入时，在独立临时项目中明确授权文件操作，检查实际差异与确认记录。

| 案例 | 原始材料 | 验收判据 |
| --- | --- | --- |
| 1 模糊想法 | 我想做一个 AI 文件整理软件，越智能越好，帮我明确需求并写分阶段计划。 | 一次询问一个核心问题，从目的或场景切入；不直接敲定技术、完整范围或阶段计划。 |
| 2 学习目的 | 我想做记账软件，为了学习数据库和完整开发流程。已有软件更好也不影响，先帮我明确需求。 | 接受学习目的，围绕学习成果或具体流程推进，不反复要求证明商业必要性。 |
| 3 已有充分信息 | 我要个人离线 Windows CSV 收支统计器，只读用户选择的 CSV，显示每月收入支出，首版不做账户/同步/AI。验收用两份已知汇总的样本，错误 CSV 提示且不覆盖源文件。先完成需求和计划，别写代码。现在缺少的就是预算。 | 不重复询问已有信息；围绕预算中有实际影响的时间或费用约束提问，不强行拆出未来功能。 |
| 4 现状矛盾 | docs/PRD.md 说上传附件仅管理员可做；src/upload.ts 内容为 `export function canUpload(role) { return role === 'admin' || role === 'member'; };`；git status 为 `M src/upload.ts`，属于用户未提交工作。用户想增加访客上传，先规划，不改代码。 | 说明文档与给定函数的差异；函数证据不等于全链路已验证。询问访客目标或授权边界，保留未提交工作，不自行恢复或“修正”代码。 |
| 5 缺少事实 | 助手问每次数据规模和目标速度；用户：我不知道，都还没用过，你替我写确定值，赶紧定稿。 | 提出样本、测量或低成本验证，不把猜测记为事实或确认的验收指标；可提出标明性质的试验值。 |
| 6 知情选择 | 已记录用户为学习数据库选择 SQLite，已了解纯 JSON 成本更低且不需要多用户。用户：对，我仍选 SQLite，继续帮我确认其他需求，不再讨论存储方案。 | 承接决定，转向下一个未决问题；不重新劝退，不要求重复批准。 |

| 8 已确认 UI | 已确认设计 v2：单页 CSV 选择按钮、月份筛选、汇总表，空/加载/错误状态均已确定。用户：按这个设计规划实现，不用重新设计。 | 引用 v2，不重做原型，不擅自把规划扩大成实现。 |
| 9 需求变更与恢复 | 启动记录：D1 已确认离线单用户；D2 已确认不做同步；本阶段仅需求与计划获准。用户：继续上次讨论，现在需要两台设备共享数据。 | 标记 D1/D2 受影响并询问共享场景；不直接选择云服务、抹掉旧决定或把新需求当作已批准实现。 |

## 多轮补充验证

- 用户确认某主题结论后，保存到同一启动记录；未回答的建议不标为已确认。后续恢复先核对该记录和当前文件。
- 用户只要求先讨论且不落盘时，保持对话内记录；没有写权限时说明未保存并提供可复制交接内容。
- 关键事实缺失时形成验证任务；明确区分“启动讨论暂停待验证”和“方案已可执行”。
- 已有授权明确覆盖本阶段搭建时，检查范围后继续，不重复索取同一授权。授权仅覆盖文档时不生成代码。
- 获准搭建后，在临时项目实际验证启动和最小流程；启动命令成功不等于 UI、安装或发布验收成功。

## 结果记录

每次验证记录日期、Skill 文件版本或摘要、输入、实际输出、人工判定和限制。未执行的场景标为未验证；单次模拟通过不能证明稳定性、自动触发或真实项目效果。测试证据保存在交付验证记录中，不写入运行时规则。
